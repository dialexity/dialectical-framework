## The repository rule and the two scripts outside it

**The rule governs the LIBRARY (`src/`), and `src/` is clean — its only raw-Cypher sites are the four named above (verified 2026-09-17). `scripts/` is out-of-process maintenance and sits OUTSIDE the rule, deliberately, because both of its Cypher-writing scripts exist to do the two things a repository must never do.** `cleanup_stale_nodes.py` inverts both halves at once: it matches on `WHERE n.hash IS NULL` (the committed-only rule backwards, because abandoned HEAD nodes are exactly what it reaps) and makes `--sid` OPTIONAL (sid scoping backwards, because a reaper that can only run per-case cannot reap a case whose sid nobody kept). It also calls `graph_db.execute()`, a verb no repository uses. `cleanup_degenerate_cycles.py` is sid-required and committed-only, but it DELETES committed structure, which the immutability contract forbids everywhere inside the library. Neither belongs behind a repository method: exposing them in-process would put an unscoped delete one import away from a tool. **What this does NOT license is a third script that merely finds a repository inconvenient** — the test is whether the query is impossible to express under the rule, not whether it is easier without it.

## Hash lookups by prefix, predicate by needle length

**Hash lookups accept a PREFIX, and the predicate is chosen by the needle's LENGTH.** Any query taking a caller- or LLM-supplied hash goes through `hash_match` (`find_by_hash`, `find_by_hashes`, `nexus_repository`), so both forms the framework hands out are usable to look the node back up: **full hash on creation** (`AddInput`, `CreateDxInput` — the caller gets something unambiguous to store) and **`short_hash` everywhere it is rendered into a prompt** (to save tokens). Ambiguous prefixes raise rather than guess — substituting some other node's content into an analysis is worse than refusing. An equality match here is a silent break: `ingest` reported `short_hash`, looked it up by equality, resolved nothing, and reported success while advising the model to stop ingesting. In-process comparison of two full hashes (e.g. `transformation_repository`) stays exact — this rule is about lookups, not comparisons. **A needle that is ALREADY full length is compared with `=`, and that is not an exception to the rule but the same question asked in the form the index can answer** — every hash is a sha256 hexdigest, so all hashes are the same length, so no string can be a strict prefix of another of equal length. Only `=` is a point lookup on `Node(hash)`; `STARTS WITH` against a parameter makes Memgraph scan the case. Short needles keep `STARTS WITH`, so nothing about the contract above changes. Never hand-write either predicate at a call site — call `hash_match(needle)` (`graph/repositories/node_repository.py`), which is where the branch and its reasoning live (`tests/test_hash_lookup_predicate.py`).

## Uncommitted node safety (`saved_at`) and the three wheel reads

**Uncommitted node safety (`saved_at`):** `save()` sets `saved_at`; `commit()` clears it. `saved_at != NULL, hash == NULL` = actively building or abandoned garbage. All listing/discovery queries MUST filter `WHERE n.hash IS NOT NULL`. Cleanup: `scripts/cleanup_stale_nodes.py --max-age 86400`, which nothing schedules — wiring the reaper is the host app's job. **That MUST was unenforced in two of the three wheel reads until 2026-09-15, and the build order makes the gap reachable, not theoretical:** `_build_wheels_for_cycle` commits the parent Cycle FIRST, then `wheel.save()`s, attaches every Transition, connects the Cycle, and commits last — so a run that stops in that window leaves a Wheel with the full transition count, a matching canonical signature, and a committed Cycle pointing at it. `find_by_component_sequence` then returns the ghost as a DEDUP HIT (the caller `continue`s past building a real wheel, so the exploration ends one short while believing it reused one) and `find_by_layer` returns it as a COMPETING ALTERNATIVE into probability normalisation, the synthesis sub-wheel dump and the presented exploration. `find_by_nexus`, next to both, always had the filter. `CycleRepository.find_by_layer` got the same predicate as a guard, not a fix: no path `save()`s a Cycle before committing it, so the Cycle side was safe by how callers happen to build them rather than by the query. Tests: `test_uncommitted_wheel_visibility_graph.py` — which also pins the other half, that the predicate does not hide committed structure. **A THIRD instance surfaced 2026-09-15 and the generalisable lesson is that grepping the repositories could not have found it:** `DialecticalContext._get_cycle_wheels` reaches wheels by TRAVERSAL (`cycle.wheels.all()`), not by query, so the abandoned wheel above was rendered straight into the counsel prompt as an arrangement that produced nothing (`### Wheel [[None]]` — `short_hash` returns None when `hash` is None). When an invariant is about node state, enumerate every way the node is REACHED, traversals included. Pinned by `test_layer_visibility_graph.py::TestAnAbandonedWheelIsNotRenderedAtAll`.

## No hash-recipe version stamp (accepted gap)

**No node records WHICH hashing recipe produced it, and that is an accepted unowned gap rather than an oversight.** `BaseNode.compute_hash()` is sha256 over the structure parts + `intent` + `committed_at`, and structural containers fold their children's hashes into their own, so a node's hash IS its claim about what it was built from and `commit()` dedups on it. Nothing stored anywhere says which version of that recipe ran. So the first change to the recipe — a new field entering a hash, a formatting change to `intent`, an added normalisation, a separator other than `"\n"` — makes identical content hash differently from what a live database already holds, and **nothing errors**: dedup stops matching (a second copy of the same Statement under a new hash), already-committed containers keep naming children by the old hashes so their Merkle claim silently stops verifying, and a case ends up half in each recipe with no marker to detect the mix, refuse it, or migrate on. Reviewed 2026-09-17 and deliberately NOT built, because no recipe change is planned and a stamp would guard nothing yet; the whole of it is one integer field written at commit plus a guard in `commit()` refusing to write into a case whose committed nodes carry a different number. **The one moment it is too late to add is right after the recipe moves**, so treat any edit to `compute_hash()` or to a `_collect_structure_hash_parts()` as the trigger to build it FIRST.

## The application owns Case creation

**The application owns Case creation; the framework only reads scope.** The app creates the `Case` and injects its `sid` as the scope the whole round works on (`graph/scope_context.py`). Nothing in `src/` creates a Case, and nothing should: one the framework invented would be a second scope root whose sid the app never learns, making every node written under it invisible to the app's own listings. So `AddInput`/`CreateDxInput` refuse rather than auto-create, via `CaseRepository.require_for_current_scope()` — which distinguishes **no sid in context** (`MissingScopeError`; scope never entered, or entered outside the task that ran the work) from **sid set but no Case** (`ValueError`). Keep them distinguishable: collapsing both into one message is why an archived e2e `ingest` failure against a committed, in-scope Case is still recorded as open in `tests/e2e/rounds.md` rather than explained. Agent chat entry points already guard with `require_current_sid()`.
