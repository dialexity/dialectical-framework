## Cycle vs Wheel, and the query levers on the combination path

**Cycle vs Wheel:** Cycle = ordered T-causality sequence (which thesis causes which). Wheel = full circular TA-arrangement with transitions (`generate_compatible_sequences`, diagonal symmetry: T_i opposite A_i). Rotated Cycles are rotations of one directed circle; Wheels are rotation-invariant (`WheelRepository.find_by_component_sequence`), so sibling Cycles share Wheel nodes. All scoped by `sid`. **That rotation-invariant lookup was the single largest cost in the tree and is now cached, per wheel, in `WheelRepository._signature_of`.** It is called once per candidate arrangement and asks the DB for every wheel of the right size, then read each one's components to compare — so each new arrangement re-read every wheel already built at that size, at 1 + 4N queries a read, because `Wheel.statements` reads `self.edges`, `edges` runs `order_transitions` which walks the chain with its OWN `source.get()`/`target.get()`, and the `statements` loop then reads both endpoints again. At k=4 perspectives (24 cycles, 96 wheels) that one call site opened 196,568 of 303,101 charges, 65% of all client traffic; caching the signature took `build_wheels` from **145.1s to 44.8s** wall and the synchronous combination phase from 115.3s to 22.6s, cutting `execute_and_fetch` 300,517 -> 120,309. Safe because a wheel's transitions are written once at creation and nothing in the framework rewires or deletes them; keyed by internal node id on the same grounds, bounded at 50k entries, and `clear_signature_cache()` exists for tests, which DO delete (wired into `cleanup_test_graph_data`). **The reasoning is untouched and the counts are the evidence** — 24 cycles / 96 wheels / 2,144 `save_node` / 2,821 `save_relationship` / 1,750 effects, identical before and after. Measured by `tests/probe_build_wheels_offprovider.py` (free, mocked, `DIALEXITY_PROBE_BW_K=4`, ~50s; `DIALEXITY_PROBE_BW_SITES=1` adds call-site attribution and inflates the seconds). **Five further levers landed on the same path, and together the six take `build_wheels` from 145.1s to 19.3s wall and `execute_and_fetch` from 300,517 to 67,556 (-78%) at k=4.** `immutable=True` is an opt-in flag on a relationship DECLARATION: it memoises a non-empty `all()` on the source node INSTANCE, and it is declared on exactly two edges, `Transition.source` and `Transition.target`. Safe there because both endpoints are connected exactly once inside `commit()`, which raises if the node is already committed, and `_validate_structural_immutability` blocks a later connect/disconnect besides — so they cannot change under a memo. What it guards is writes through the same manager (`connect`/`disconnect` invalidate); what it does NOT guard is a write to the same edge through a DIFFERENT Python object for the same node, or raw Cypher, which is why it is per-declaration and belongs only on edges the owning node freezes at commit. Two guards keep an empty read out of the memo — `_store_all` refuses to store one, `_connect_internal` invalidates before writing — and mutation testing showed they are REDUNDANT for this path: removing either alone leaves the suite green and only removing BOTH regresses, so **do not delete one on the grounds that tests still pass** (recorded in `tests/test_immutable_relationship_cache.py`, which also records that two of its own assertions were vacuous until mutation caught them). That took IS_SOURCE_OF 34,332 -> 18,282 and IS_TARGET_OF 26,865 -> 17,256. **`RelationshipManager.prefetch(nodes)` is the lever the per-instance memo could not reach**, and it is the bigger one: `Wheel.edges` builds a FRESH transition list on every access, so the memo started cold each time and only made the SECOND pass (`statements` re-reading the same endpoints) free — ordering the chain still paid 2N round-trips. `Wheel.edges` now calls `Transition.source.prefetch(all_edges)` and `.target.prefetch(...)`, two batched reads that fill every transition's memo up front, so one traversal costs 3 round-trips instead of 2N+1 (endpoint charges 35,538 -> 15,808; combination 18.4s -> 11.5s). It refuses a non-`immutable` declaration (the memo would be written and never read), groups rows under the same `ORDER BY` as `all()` so a primed memo holds exactly what that node's own read would have, and leaves a node the query returned nothing for UNPRIMED rather than primed-empty. **The reasoning is untouched and the counts are the evidence for all three** — 24 cycles / 96 wheels / 2,144 `save_node` / 2,821 `save_relationship` / 1,750 effects, identical at every step. **Read charges, not wall, between the signature cache and the memo**: the wall rose 44.8s -> 48.8s while charges fell 21%, because per-query latency moved 0.32 -> 0.43ms on the same box and the mocked estimation phase swings 16-25s run to run; only the cumulative 4.8x is a clean figure. **The fourth lever is `hash_match` in `graph/repositories/node_repository.py`, and it is a SCALING fix rather than a constant-factor one.** `find_by_hash` is the framework's most-used read (4,099 calls in one k=4 build, nearly all of them `BaseNode.commit` passing a node's OWN full hash to dedup it) and it asked `n.hash STARTS WITH $hash`. Memgraph cannot make a point lookup out of `STARTS WITH` against a parameter, so the planner fell back to `ScanAllByLabelProperties (n :Node {sid})` — every node in the case, then filtered — making the hottest read O(case size). A full-length needle is now compared with `=`, which IS a point lookup on the `Node(hash)` index. **This is not a behaviour change and the prefix contract is untouched:** every hash is a sha256 hexdigest, so all hashes are the same length, so no string can be a strict prefix of another of equal length — `STARTS WITH <64 chars>` and `= <64 chars>` select the same nodes. Short needles still use `STARTS WITH`, because `short_hash` is what the framework renders into prompts and a lookup must accept it (matching on equality only is the bug that once broke `ingest` silently). `find_by_hashes` partitions its batch by length and runs one query per form. **Do not quote the wall for this one.** It is worth ~1s of a 24s k=4 run (that shape: 0.617 -> 0.374ms, 2.53s -> 1.53s, charge count unchanged) because the probe database holds only ~2,100 nodes. `tests/probe_hash_lookup_scaling.py` measures both curves at several case sizes and is where the real claim lives: equality is FLAT (823/875/805us at 200/1000/4000 nodes) while the prefix scan grows linearly in the scan component (0.40/0.53/0.55us per node), so on a 50k-node case the old form would cost ~27ms per lookup. **The fifth and sixth levers both remove a question that was already being asked, and they take the k=4 wall to 19.29s and `execute_and_fetch` to 67,556.** (5) **`BaseNode.commit()` no longer calls `find_by_hash` before `save()`** — `save()` runs the identical lookup under identical conditions (`hash` set, `_id is None`) and nothing between them can change the answer, so every commit on that path paid two identical round-trips. It now delegates with `if self._id is None: return self.save()`. The `_id is not None` branch KEEPS its own lookup, because `save()`'s dedup guard requires `_id is None` and would skip dedup entirely there. **This one was predicted to the unit before it was made:** the write probe attributed 1,376 charges to `find_by_hash < save < commit`, a miss costs 2 charges (open + StopIteration), so 688 duplicate calls had to be exactly 552 estimations + 112 rationales + 24 cycles, and removing them had to take the shape from 4,099 to 2,723 charges. It did. (6) **`PerspectiveRepository.find_by_statements` batches `Wheel._perspectives`' 2N per-endpoint lookups into one query** — the lever named as "next" in the note this replaces. That shape went from the most expensive in the run (2.96s) to sixth (0.84s). The care it needed was NOT in the query: **`_perspectives` order is load-bearing** — it becomes the wheel's `polar_segments`, and `sequence_generation` documents its input as priority order — so the caller still drives the loop from `edges` and the result is pinned differentially against a copy of the old per-component loop (`tests/test_perspectives_batched_lookup.py`), including a shape where chain order deliberately opposes node-id order. That last shape exists because mutation testing showed the first four were VACUOUS about ordering: an implementation iterating the result map instead of the edges passed all of them. **A pre-existing crash surfaced while pinning (5) and was deliberately NOT fixed:** committing a duplicate `Estimation` directly raises `ValueError: maximum cardinality 1 already reached`, because `Estimation.commit()` re-connects the target after delegating up and on a dedup hit `self._id` is the EXISTING node, which already holds that edge. It raises identically without lever (5), and production never reaches it because `EstimationManager._get_or_create_estimation` queries for a matching `(e {value})-[:ESTIMATES]->(target)` first — so Estimation's dedup-hit path is dead code guarded by the manager, and making it live is a reasoning decision about what a duplicate estimation means. Also noted, not changed: `Statement.commit()` runs its OWN `find_by_hash` for the Input-collision check before delegating, so a Statement commit was three identical lookups and is now two; the check guards a different condition and carries a TODO about extending it to all content-addressable nodes. **After all six, the phase that dominated no longer does:** COMBINATION 9.88s vs ESTIMATION 8.77s of a 19.29s wall, where the baseline was 116s vs 28s — and the estimation half is mocked, carrying 1,102.8s of real provider time. Off-provider wall was 84% of the paid k=4 run and is now roughly a quarter of it, so this path is no longer where wall-clock lives; "provider" here means the LLM API, and it is now the whole story on this path. **Still UNSAFE:** a plain memo on `Wheel.edges`, re-traversed per wheel by six callers. Transitions attach via `transition.cycle.connect(wheel)`, a write through a different manager on a different node — precisely the case the flag does not guard — and `_build_wheels_for_cycle` reads wheels mid-build.
